# 哑铃运动研究（2026-11-15）

对象：`scripts/life/exercise_session.gd` 里 `kind=="weights"` 的哑铃训练（健身房 4 件器材之一）。
方法：headless 起游戏 → 走到哑铃架操作位 → `exercise_session.begin()` → 以 60 Hz 逐帧推进 360+200 帧，逐帧采样 `LeftArm / LeftForeArm / LeftHand / Spine / Hips / Head` 的骨骼世界坐标，再换算成相对肩关节的前后、左右、上下距离。不是看图说话，全部是可复现的数值。

## 二、和真实哑铃弯举对照

真实站姿交替弯举的四个硬特征：

1. **肘钉在体侧**：肘关节几乎只做旋转，前后左右位移应 < 3 cm。
2. **顶端到肩不过肩**：哑铃到锁骨/肩高就停，手不会比肩高 10 cm、更不会贴到脸。
3. **前臂在矢状面里屈伸**：腕在手-肘连线上，肘向“下后方”弯，不是向外张开。
4. **掌心有旋后**：底端掌心朝身（锤式），顶端掌心朝上，游戏里至少手骨要有这个旋转，否则哑铃只是浮在腕上。

当前实现四条全不满足：

- 顶端比肩还高 10.8 cm、离头 3.7 cm → 看起来是在做「身前上举」而不是弯举。
- 肘上下 25 cm、外扩 21 cm → 因为 `_reach_arm` 的弯肘轴是 `direction.cross(UP)`（`player_controller.gd:346`），目标点一旦接近竖直，叉积退化，回退成 `Vector3.RIGHT`，肘就被往侧面推。
- 手骨只给了位置，没有给朝向（`exercise_session.gd:116-121` 只算 `hand_target`），所以全程不旋后，杆是横的但手掌没在握。
- 哑铃中心落在腕骨 +0.02 m（`exercise_session.gd:135`），不在掌心；杆看着像穿在手腕上。

## 三、根因（代码定位）

| 现象 | 位置 | 原因 |
|---|---|---|
| 手抬过肩/贴脸 | `exercise_session.gd:119-121` | 目标高度 `1.18+0.5*curl`，顶端系数过大（相当于肩高 +0.5 倍体高系数），没有按「肩高」封顶 |
| 肘外扩、跟着手抬 | `player_controller.gd:346-348` | 两段 IK 用 `direction.cross(UP)` 当弯肘轴，近似竖直目标时退化，肘被甩向外侧；且没有任何「肘钉住」的约束 |
| 掌心不旋后 | `exercise_session.gd:116-121` 未设置手骨旋转 | 只覆盖位置（`_reach_arm` 里 `c.origin=wrist`），手骨朝向沿用待机姿势 |
| 杆卡在腕上 | `exercise_session.gd:135` | 偏移 `front_axis*.02`，应沿手掌方向推一个掌厚（~0.05 m）并随腕旋转 |
| 没有次数 | `exercise_session.gd:139` | 面板只累加 `elapsed` 秒 |

## 四、建议改法（可直接照做，不改玩法经济）

1. **肘先定点，再解前臂**：新增 `_curl_arm(side, flex)`：肘固定在 `肩 + 侧向0.20·s + 下0.26 + 后0.03`；前臂绕肘在“前-上”矢状面内旋转，`flex` 从 12° 到 142°；腕 = 肘 + 前臂长×方向。这样肘位移压到 <2 cm，手顶到肩高即停。
2. **手的高度封顶**：目标手位改为 `肩高 + 0.02`，底端 `髋 - 0.06`，前后固定 0.16 m，侧向 0.20 m。
3. **加旋后**：手骨 global override 绕前臂轴加 `0→80°` 的旋转（底端锤式、顶端掌心朝上），哑铃杆的朝向跟着手骨基，别再用世界基固定。
4. **握点推进掌心**：哑铃中心改成 `腕 + 手骨前向 0.05 m`。
5. **加次数**：用 `flex` 的相位过零计次，面板改「第 N 次 · 强度X · 已练 Y 秒」；强度只改相位速度，不改幅度，避免高强度的动作变形。
6. 顺手：`_reach_arm` 的退化回退轴改成「取上一次有效轴」而不是写死 `Vector3.RIGHT`，钓鱼/喝水/开冰箱那些弯肘动作也会一起变稳。

## 五、风险

- 哑铃分支是`gym_weights` 独占，改动不碰跑/划船/钓鱼；`test_home_interaction_paths` 里有一条「weights 时右手会动」的断言，改后仍应通过。
- 加次数只是显示，不改 `energy/thirst` 消耗公式；强度仍按 `pace` 放大消耗。
- 手骨旋后用 global override，会和 `gesture.clear()` 的还原路径共用，需确认退出后手骨回正（现有 `release_pose` 会整体还位姿）。

## 六、结论

哑铃现在不是「丑一点」，而是**动作语义错了**：它做的是「身前上举 + 开肘」，不是弯举。要修就修上面 1–5 五条，改动集中在 `exercise_session.gd` 的 `weights` 分支和 `player_controller._reach_arm` 的弯肘轴一行，不动经济与其它器材。

## 七、已修复（装机 1608）

按上面 1–5 条改完，六条兜底也顺手做了，复测结果：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 肘上下行程 | 25.0 cm | **4.8 cm** |
| 肘左右行程 | 20.9 cm | **1.9 cm** |
| 手最高点 | 肩高 +10.8 cm（离头 3.7 cm） | **肩高 −3.0 cm**（离头 17.5 cm） |
| 手最低点 | 髋上 7 cm | 髋下 6.7 cm |
| 手上举行程 | 47.3 cm | 33.5 cm（受前臂长度与肘位约束的真实上限） |
| 哑铃到腕骨 | 2.0 cm | **3.5 cm（落在掌心）**，杆轴保持横向 |
| 面板 | 只有秒数 | **「第 N 次 · 强度X · Y秒」**，次数来自相位过零 |

实现：`exercise_session.gd` 新增 `_curl_arms()`——肘用待机姿势里的大臂位姿固定不动，前臂在“前-上”矢状面里从 8° 屈到 150°，手骨同步旋后（顶端 75°），哑铃沿前臂方向前推 4.5 cm 落在掌心；`player_controller._reach_arm` 的弯肘轴退化时改为沿用上一次有效轴（不再写死 RIGHT），喝水/开冰箱那些弯肘动作一并变稳。

回归：`FIXED SKILL SLOTS 167/0`、`HOME INTERACTION PATHS 91/2`（两条仍是既有钓鱼视角红项，未新增）、`LIFE 55/0`。
