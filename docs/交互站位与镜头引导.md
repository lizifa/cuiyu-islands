# 交互站位与镜头引导 · 0.7.1

## 操作规则

靠近物体只显示交互按钮与推荐站位圈，不自动转身或转动镜头。点击后进入“走到站位 → 平滑面向目标 → 执行动作”，过程中右下可取消，摇杆可立即接管。行走使用现有角色物理移动，受树根、动物、家具和建筑阻挡；没有穿过障碍或传送到站位的捷径。站位被占据、找不到路线或持续受阻时提示重试，尚未执行的动作不扣材料、不发奖励。

伐木、拾石、采纤维在就位后播放既有劳作动作，完成再结算一次；途中取消无结算。其他生活交互保留既有成本及动作。暂停、菜单和后台冻结流程；地点、楼层、角色或建筑状态变化使待执行交互失效，重置游戏直接清空待执行回调。

## 各类交互

| 对象 | 站位与朝向 | 取景 |
|---|---|---|
| 钓台 | 从通道走到凳前，面向开阔海面后甩竿 | 人物侧后方，随后沿用浮漂与抄网阶段取景 |
| 树木、石材、纤维、果实 | 按实际操作余量在目标外侧选择可达位置 | 侧后方观察人物和操作点 |
| 沙发 | 先到座位前再转身入座 | 观察人物及客厅电视方向 |
| 房门、楼梯 | 在入口外或楼梯操作点就位，面向通过方向 | 保留进出场景的既有室内外取景 |
| 船 | 在码头登船点面向小船 | 进入航行后使用船后侧视角 |
| 炉灶、水槽、餐桌、床、储物处、浴室、摊位 | 对应操作面前站稳并转向目标 | 使用室内或商铺推荐角度 |

自动任务沿用已有寻路，到达后也先平滑转向，再施工、采集或登船。未修好的船仍先展示修船与补给流程。移动中的宠物沿用其已有的动态接近、朝向与抚摸流程，不给它强加固定地面站位。海上靠岸继续使用物理返航流程。

## 镜头控制权

推荐镜头只在交互开始时平滑设置，不持续锁住用户视角。用户拖动镜头、点击视角归位或看太阳后，当前流程交还镜头控制；钓鱼后续的收线、抄网阶段及退出均不覆盖这次手动选择。下一次主动发起交互可重新采用该物体的推荐取景。镜头仍经过既有地形高度和遮挡约束；推荐角度是按动作设计的预设，不是自动构图识别。

## 预制体配置

InteractionAnchor继承Marker3D，归属于交互物体或场景根节点。包含站位、FacingTarget和RecommendedCamera子标记。树木锚点归属于对应树，钓台锚点归属于钓台，室内锚点归属于别墅场景。已有静态interaction_points统一注册；新增点可以填写owner、stand、facing、camera_offset和radial覆盖默认规则。位置使用世界坐标注册，再转换为所属节点的局部变换，物体变换后标记随之移动。

径向资源点从人物来向附近挑选安全位置，给动作留出余量；固定家具优先使用指定站位，必要时在附近25厘米内找净空。岛屿复用已有寻路图，室内建立局部网格。就位检测复用查询形状，并在一次请求中缓存地面排除列表，避免为每个格子反复遍历森林节点或创建碰撞形状。

## 验证边界

新增INTERACTION ANCHORS 23项，覆盖真实行走、分帧转身、一次劳作结算、取消就位/动作、暂停、受阻拒绝、镜头手动接管、钓鱼后续阶段保留视角及重置清除旧回调。原触控用例更新为等待实际就位，并使用可通行的采果站位；抚摸在稳定姿态采样。连同既有回归共1042项计数检查通过，UI smoke零失败，最终有效日志无SCRIPT ERROR或ERROR。

未打开预览或自动启动手机游戏。以上为headless物理和状态验证，真机转镜舒适度、动作美感及长时间热性能未重新测量。
